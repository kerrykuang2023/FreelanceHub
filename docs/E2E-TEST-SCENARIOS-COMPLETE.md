**文档版本:** v2.0  
**创建日期:** 2026-03-25  
**测试原则:** 前后端数据一致性验证 + 动态业务流程验证

## 1. 测试原则

### 1.1 核心验证原则

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                           测试验证原则                                        │
└─────────────────────────────────────────────────────────────────────────────┘

1. 数据前置条件验证
   ├── 验证操作前数据存在
   ├── 验证数据状态正确
   └── 验证数据关联关系

2. 操作执行验证
   ├── 验证UI操作成功
   ├── 验证API调用成功
   └── 验证无控制台错误

3. 数据后置条件验证
   ├── 验证前端数据变化
   ├── 验证后端数据变化
   └── 验证前后端数据一致

4. 状态流转验证
   ├── 验证状态转换正确
   ├── 验证关联数据更新
   └── 验证业务规则满足
```

### 1.2 验证流程模板

```typescript
async function verifyBusinessFlow(options: {
  role: 'freelancer' | 'hr' | 'admin';
  operation: string;
  preConditions: () => Promise<void>;
  execute: () => Promise<void>;
  postConditions: () => Promise<void>;
  verifyFrontend: () => Promise<any>;
  verifyBackend: () => Promise<any>;
  expectedChanges: {
    status?: { from: string; to: string };
    count?: { field: string; change: number };
    data?: { field: string; expectedValue: any };
  };
}) {
  // 1. 验证前置条件
  await options.preConditions();
  
  // 2. 获取操作前数据
  const beforeFrontend = await options.verifyFrontend();
  const beforeBackend = await options.verifyBackend();
  
  // 3. 执行操作
  await options.execute();
  
  // 4. 等待数据同步
  await page.waitForTimeout(2000);
  
  // 5. 获取操作后数据
  const afterFrontend = await options.verifyFrontend();
  const afterBackend = await options.verifyBackend();
  
  // 6. 验证数据变化
  if (options.expectedChanges.status) {
    expect(afterBackend.status).toBe(options.expectedChanges.status.to);
    expect(afterFrontend.status).toBe(options.expectedChanges.status.to);
  }
  
  // 7. 验证前后端一致性
  expect(afterFrontend).toEqual(afterBackend);
  
  // 8. 验证后置条件
  await options.postConditions();
}
```

#### 场景 F-WL-01: 创建工时记录

```
┌─────────────────────────────────────────────────────────────────────────────┐
│ 场景: F-WL-01 创建工时记录                                                   │
└─────────────────────────────────────────────────────────────────────────────┘

前置条件:
  - 求职者已登录
  - 存在进行中的项目
  - 求职者已分配到项目

操作步骤:
  1. 导航到工时列表页面
  2. 点击"新建工时"按钮
  3. 选择项目
  4. 填写工时信息(日期、小时数、描述)
  5. 点击"保存草稿"

验证点:
  ├── 前端验证
  │   ├── 工时列表数量 +1
  │   ├── 新工时显示在列表中
  │   └── 新工时状态显示为"草稿"
  │
  ├── 后端验证
  │   ├── 数据库工时记录 +1
  │   ├── 新记录status = 'draft'
  │   ├── freelancer_id = 当前用户ID
  │   └── project_requirement_id = 选择的项目ID
  │
  └── 一致性验证
      ├── 前端显示数量 = 后端查询数量
      ├── 前端显示状态 = 后端记录状态
      └── 前端显示工时 = 后端记录工时

预期结果:
  - 工时创建成功
  - 前后端数据一致
  - 状态正确为"draft"
```

```
流程步骤:
  1. HR发布项目
     ├── 验证: 项目创建成功
     └── 状态: published

  2. 求职者申请项目
     ├── 验证: 申请创建成功
     └── 状态: pending

  3. HR批准申请
     ├── 验证: 申请状态更新
     ├── 验证: 项目分配顾问
     └── 状态: pending → approved

  4. 求职者填报工时
     ├── 验证: 工时创建成功
     └── 状态: draft

  5. 求职者提交工时
     ├── 验证: 工时状态更新
     └── 状态: draft → submitted

  6. HR确认工时
     ├── 验证: 工时状态更新
     └── 状态: submitted → confirmed

  7. 求职者创建发票
     ├── 验证: 发票创建成功
     ├── 验证: 工时状态更新
     └── 状态: confirmed → invoiced

  8. 求职者提交发票
     ├── 验证: 发票状态更新
     └── 状态: draft → submitted

  9. HR审批发票
     ├── 验证: 发票状态更新
     └── 状态: submitted → approved

  10. HR确认付款
      ├── 验证: 发票状态更新
      └── 状态: approved → paid

  11. 求职者确认收款
      ├── 验证: 发票状态更新
      └── 状态: paid → received

每个步骤验证:
  - 前端数据正确显示
  - 后端数据正确更新
  - 前后端数据一致
```
