## 1. 产品概述

### 1.1 产品背景

随着灵活用工市场的快速发展，越来越多的专业顾问（如SAP顾问、IT专家、行业咨询顾问等）选择以自由职业者的身份参与项目。然而，当前市场上缺乏专门针对专业顾问群体的项目管理平台，导致以下问题：

- **信息不对称**：顾问难以找到合适的项目，企业难以找到合适的顾问
- **工时管理混乱**：工时填报、确认流程繁琐，缺乏标准化工具
- **结算流程复杂**：发票开具、税务计算、多方结算缺乏系统支持
- **信任机制缺失**：缺乏评价体系和信用背书，合作风险高

### 1.2 产品定位

本产品定位为**专业自由顾问项目管理平台**，聚焦于：

- 专业顾问（SAP、IT、咨询等）的项目匹配与工作管理
- 工时填报、确认、结算的全流程数字化
- 多方协作（顾问-挂靠企业-外包公司-终端企业）的透明化管理
- 合规的发票开具与税务处理

### 1.3 产品目标

| 目标类型 | 具体目标 | 衡量指标 |
|----------|----------|----------|
| 业务目标 | 打造专业顾问首选的项目管理平台 | 平台注册顾问数 > 10,000 |
| 用户目标 | 提高顾问项目获取效率和收入稳定性 | 顾问月均项目参与率 > 80% |
| 运营目标 | 建立健康的平台生态和信任机制 | 平台交易额年增长率 > 100% |
| 技术目标 | 构建稳定、安全、可扩展的平台架构 | 系统可用性 > 99.9% |

### 1.4 产品范围

#### 1.4.1 包含范围

- 用户注册、认证、档案管理
- 项目需求发布与智能匹配
- 工时填报、审核、确认流程
- 发票开具与付款追踪
- 消息通知与沟通
- 评价与信用体系
- 数据统计与报表
- 平台管理与配置

#### 1.4.2 不包含范围

- 传统招聘求职功能（简历投递、面试安排等）
- 在线支付功能（对接第三方支付）
- 移动端App（后期规划）
- 企业内部HR管理功能

### 2.2 角色详细定义

#### 2.2.1 自由顾问 (Freelancer)

| 属性 | 描述 |
|------|------|
| **角色定义** | 以项目制工作的专业顾问，如SAP顾问、IT专家、咨询顾问等 |
| **子类型** | 独立顾问、挂靠顾问、团队顾问 |
| **核心诉求** | 快速找到合适项目、高效管理工时、及时获得付款 |
| **主要功能** | 档案管理、项目申请、工时填报、发票管理、收入统计 |

#### 2.2.2 挂靠企业 (Affiliation Company)

| 属性 | 描述 |
|------|------|
| **角色定义** | 为自由顾问提供挂靠服务的公司，负责开票、税务、社保等 |
| **核心诉求** | 高效管理挂靠顾问、简化开票流程、及时分账结算 |
| **主要功能** | 顾问管理、工时审核、发票开具、分账结算、财务报表 |

#### 2.2.3 外包公司/猎头 (Outsourcing Company)

| 属性 | 描述 |
|------|------|
| **角色定义** | 承接企业项目需求，匹配顾问资源的服务公司 |
| **子类型** | 外包公司、猎头公司 |
| **核心诉求** | 高效匹配资源、透明管理项目、优化利润空间 |
| **主要功能** | 项目发布、顾问调度、进度监控、工时审核、结算管理 |

#### 2.2.4 终端企业 (End Client)

| 属性 | 描述 |
|------|------|
| **角色定义** | 有项目需求、需要外部专业顾问支持的企业 |
| **核心诉求** | 找到优质顾问、透明项目进度、控制项目成本 |
| **主要功能** | 需求发布、顾问筛选、工时确认、成果验收、付款管理 |

#### 2.2.5 平台管理员 (Admin)

| 属性 | 描述 |
|------|------|
| **角色定义** | 平台运营人员，负责平台整体运营和管理 |
| **核心诉求** | 高效审核管理、数据透明可控、平台健康运营 |
| **主要功能** | 用户管理、企业管理、技能管理、系统配置、数据监控 |

### 4.2 用户认证模块

#### 4.2.1 功能描述

#### 4.2.3 详细需求

**AUTH-001 用户注册**

| 属性 | 描述 |
|------|------|
| **功能名称** | 用户注册 |
| **功能描述** | 新用户通过邮箱或手机号注册账号 |
| **前置条件** | 无 |
| **后置条件** | 用户账号创建成功，处于待认证状态 |
| **输入** | 邮箱/手机号、密码、确认密码、用户角色 |
| **输出** | 注册成功/失败提示 |
| **业务规则** | 1. 邮箱/手机号格式校验<br>2. 密码强度校验（至少8位，包含字母和数字）<br>3. 邮箱/手机号唯一性校验<br>4. 发送验证码/验证邮件 |
| **异常处理** | 1. 邮箱/手机号已存在：提示"该账号已注册"<br>2. 验证码错误：提示"验证码错误"<br>3. 密码强度不足：提示密码要求 |
| **UI原型** | 注册页面包含：邮箱/手机号输入框、验证码输入框、密码输入框、角色选择下拉框、注册按钮 |

**AUTH-002 企业注册与认证**

| 属性 | 描述 |
|------|------|
| **功能名称** | 企业注册与认证 |
| **功能描述** | HR用户注册后完善企业信息，申请企业认证 |
| **前置条件** | 用户已选择HR角色完成注册 |
| **后置条件** | 企业信息创建成功，进入认证审核流程 |
| **输入** | 企业名称、所属行业、企业规模、企业地址、联系人、联系电话、营业执照（图片上传） |
| **输出** | 企业创建成功/失败提示 |
| **业务规则** | 1. HR注册成功后自动跳转到企业信息完善页面<br>2. 企业名称不能重复<br>3. 营业执照必传，支持jpg/png/pdf格式<br>4. 企业信息提交后进入待审核状态<br>5. 管理员审核通过后企业认证状态更新为"已认证" |
| **流程设计** | 见下方企业注册流程图 |
| **异常处理** | 1. 企业名称已存在：提示"该企业名称已被使用"<br>2. 营业执照格式错误：提示支持的格式<br>3. 营业执照大小超限：提示最大文件大小 |
| **UI原型** | 企业信息完善页面包含：企业名称输入框、行业选择下拉框、企业规模选择、地址输入框、联系人输入框、联系电话输入框、营业执照上传区域、提交按钮 |

| **推荐算法** | 见下文 |
| **输出** | 匹配度评分、推荐理由 |

**推荐算法设计：**

```
匹配度计算公式：
MatchScore = W1 * SkillMatch + W2 * LocationMatch + W3 * RateMatch + W4 * AvailabilityMatch

其中：
- SkillMatch (权重40%): 技能匹配度
  - 完全匹配：100分
  - 部分匹配：匹配技能数/要求技能数 * 100
  - 不匹配：0分

- LocationMatch (权重20%): 地域匹配度
  - 同城：100分
  - 同省：80分
  - 同国家：60分
  - 支持远程：100分（远程项目）

- RateMatch (权重20%): 费率匹配度
  - 在预算范围内：100分
  - 略超预算（10%内）：80分
  - 超预算较多：50分

- AvailabilityMatch (权重20%): 可用性匹配度
  - 时间完全匹配：100分
  - 部分时间冲突：60分
  - 时间冲突：0分
```

**INV-008 税务计算**

| 属性 | 描述 |
|------|------|
| **功能名称** | 税务计算 |
| **功能描述** | 根据税务计算方式自动计算税额 |
| **计算规则** | 见下文 |
| **输出** | 不含税金额、税额、价税合计 |

**税务计算规则：**

```
情况1：含税价（企业承担税费）
- 输入：含税金额、税率
- 计算：
  不含税金额 = 含税金额 / (1 + 税率/100)
  税额 = 含税金额 - 不含税金额

情况2：不含税价（顾问实得）
- 输入：不含税金额、税率
- 计算：
  税额 = 不含税金额 * 税率/100
  价税合计 = 不含税金额 + 税额

示例：
- 含税价：含税金额15000元，税率6%
  不含税金额 = 15000 / 1.06 = 14150.94元
  税额 = 15000 - 14150.94 = 849.06元

- 不含税价：不含税金额15000元，税率6%
  税额 = 15000 * 0.06 = 900元
  价税合计 = 15000 + 900 = 15900元
```

### 11.5 登录与授权处理规范

> **重要说明:** 本节记录登录与授权处理过程中发现的问题、解决方案及最佳实践，用于指导后续相关功能的开发。

#### 11.5.1 核心问题与解决方案

**问题1: Token存储缺失**

| 问题描述 | 原因分析 | 解决方案 |
|----------|----------|----------|
| 登录后API请求未携带Authorization header | AuthProvider的login函数未将token存储到localStorage | 在login函数中添加`StorageService.setItem("access_token", token)` |

**问题2: 状态同步延迟**

| 问题描述 | 原因分析 | 解决方案 |
|----------|----------|----------|
| 登录后权限检查失败，用户被重定向到首页 | React状态更新是异步的，权限检查在状态更新完成前执行 | 1. 将login函数改为async/Promise模式<br>2. 添加isLoading状态<br>3. 权限检查前等待状态就绪 |

**问题3: 角色数据格式不一致**

| 问题描述 | 原因分析 | 解决方案 |
|----------|----------|----------|
| activeRole数据格式与IUserRole接口不匹配 | 后端返回的数据格式与前端类型定义不一致 | 添加normalizeActiveRole函数进行数据格式标准化 |

**usePermissions Hook实现:**

```typescript
export type RoleType = 'job_seeker' | 'freelancer' | 'hr_recruiter' | 'company_user' | 'admin';

export interface PermissionResult {
  isAuthenticated: boolean;
  isLoading: boolean;
  currentRole: RoleType;
  isHR: boolean;
  isAdmin: boolean;
  isHROrAdmin: boolean;
  isFreelancer: boolean;
  hasAnyRole: (roles: RoleType[]) => boolean;
}

export const usePermissions = (): PermissionResult => {
  const { isAuthenticated, activeRole, user, roles, isLoading } = useAuth();
  
  return useMemo(() => {
    const currentRole = (activeRole?.role_type || user?.user_type_name || 'job_seeker') as RoleType;
    const isHR = currentRole === 'hr_recruiter';
    const isAdmin = currentRole === 'admin';
    const isHROrAdmin = isHR || isAdmin;
    const isFreelancer = currentRole === 'freelancer';
    
    const hasAnyRole = (allowedRoles: RoleType[]): boolean => {
      if (!isAuthenticated) return false;
      return allowedRoles.includes(currentRole);
    };
    
    return {
      isAuthenticated,
      isLoading,
      currentRole,
      isHR,
      isAdmin,
      isHROrAdmin,
      isFreelancer,
      hasAnyRole,
    };
  }, [isAuthenticated, activeRole, user, roles, isLoading]);
};
```

#### 11.5.4 路由权限守卫实现

**RoleRoute组件实现:**

```typescript
const PERMISSION_READY_DELAY = 500;

const RoleRoute: React.FC<RoleRouteProps> = ({ children, allowedRoles }) => {
  const { hasAnyRole, isAuthenticated, isLoading } = usePermissions();
  const [isReady, setIsReady] = useState(false);

  useEffect(() => {
    if (!isLoading) {
      const timer = setTimeout(() => {
        setIsReady(true);
      }, PERMISSION_READY_DELAY);
      return () => clearTimeout(timer);
    }
  }, [isLoading, isAuthenticated]);

  if (isLoading || !isReady) {
    return <LoadingSpinner />;
  }

  if (!isAuthenticated) {
    return <Navigate to="/login" replace />;
  }

  if (!hasAnyRole(allowedRoles)) {
    return <Navigate to="/" replace />;
  }

  return <>{children}</>;
};
```

#### 11.5.8 开发注意事项

1. **登录流程必须等待完成**: 登录后必须等待token存储和状态更新完成再进行页面跳转
2. **权限检查需要延迟**: 由于React状态更新是异步的，权限检查需要等待isLoading变为false后再延迟一段时间
3. **Token存储位置**: Token必须存储在localStorage中，确保页面刷新后仍可使用
4. **角色数据标准化**: 后端返回的角色数据格式可能与前端类型定义不一致，需要标准化处理
5. **API端点验证**: E2E测试时需要验证API端点是否正确，部分端点可能需要认证

#### 11.7.2 详细数据流转规则

**规则1: 项目发布依赖**

| 依赖项 | 依赖类型 | 缺失影响 | 解决方案 |
|--------|----------|----------|----------|
| 公司信息 | 强依赖 | 无法发布项目 | 管理员先创建公司 |
| 技能分类 | 强依赖 | 无法选择技能要求 | 管理员先配置技能分类 |
| 枚举配置 | 强依赖 | 无法选择工作性质等 | 系统预置枚举值 |

**规则2: 工时填报依赖**

| 依赖项 | 依赖类型 | 缺失影响 | 解决方案 |
|--------|----------|----------|----------|
| 进行中的项目 | 强依赖 | 无法填报工时 | 先完成项目申请审批流程 |
| 公司信息 | 弱依赖 | 无法关联企业 | 项目中已包含公司信息 |
| 枚举配置 | 强依赖 | 无法选择工作类型 | 系统预置枚举值 |

**规则3: 发票创建依赖**

| 依赖项 | 依赖类型 | 缺失影响 | 解决方案 |
|--------|----------|----------|----------|
| 已确认的工时 | 强依赖 | 无法创建发票 | 先完成工时填报和确认 |
| 公司信息 | 强依赖 | 无法填写开票信息 | 管理员先创建公司 |
| 枚举配置 | 强依赖 | 无法选择发票类型 | 系统预置枚举值 |

**规则4: 付款确认依赖**

| 依赖项 | 依赖类型 | 缺失影响 | 解决方案 |
|--------|----------|----------|----------|
| 已审核的发票 | 强依赖 | 无法确认付款 | 先完成发票创建和审核 |
| 公司银行信息 | 弱依赖 | 无法记录付款信息 | 完善公司银行信息 |

#### 11.7.3 业务流程前置条件矩阵

| 业务操作 | 前置条件 | 数据依赖 | 验证逻辑 |
|----------|----------|----------|----------|
| HR发布项目 | 1. HR已登录<br>2. 存在公司记录 | 公司ID有效 | `company_id` 必须存在于 `companies` 表 |
| 顾问申请项目 | 1. 顾问已登录<br>2. 项目状态为"已发布" | 项目ID有效 | `project.status === 'published'` |
| 顾问填报工时 | 1. 顾问已登录<br>2. 存在进行中的项目 | 项目ID有效且顾问已加入 | `project.status === 'in_progress'` 且 `freelancer` 在项目成员中 |
| HR审核工时 | 1. HR已登录<br>2. 存在待审核工时 | 工时状态为"已提交" | `worklog.status === 'submitted'` |
| 顾问创建发票 | 1. 顾问已登录<br>2. 存在已确认工时 | 工时状态为"已确认" | `worklog.status === 'confirmed'` |
| HR审核发票 | 1. HR已登录<br>2. 存在待审核发票 | 发票状态为"已提交" | `invoice.status === 'submitted'` |
| HR确认付款 | 1. HR已登录<br>2. 存在已审核发票 | 发票状态为"已审核" | `invoice.status === 'approved'` |
| 顾问确认收款 | 1. 顾问已登录<br>2. 发票已付款 | 发票状态为"已付款" | `invoice.status === 'paid'` |
| 双向评价 | 1. 用户已登录<br>2. 项目已完成/已付款 | 项目状态为"已完成"或发票已付款 | `project.status === 'completed'` 或 `invoice.status === 'paid'` |

| 枚举配置 | 全量 | 所有枚举类型都需要配置 | 系统预置 |
