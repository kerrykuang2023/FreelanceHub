## 1. 工作广场模块

### 1.1 项目市场（顾问视角）

#### 功能概述
顾问浏览、搜索、投递项目的入口

#### 角色权限矩阵

| 操作 | 访客 | 顾问 | HR | 管理员 |
|------|------|------|-----|--------|
| 浏览项目列表 | ✅ | ✅ | ✅ | ✅ |
| 查看项目详情 | ✅ | ✅ | ✅ | ✅ |
| 投递申请 | ❌ | ✅ | ❌ | ❌ |
| 收藏项目 | ❌ | ✅ | ❌ | ❌ |
| 查看私有信息 | ❌ | ❌ | ✅ | ✅ |

#### 字段定义

**项目列表字段：**

| 字段名 | 类型 | 必填 | 可见性 | 说明 |
|--------|------|------|--------|------|
| project_id | string | 是 | 全部 | 项目唯一标识 |
| project_title | string | 是 | 全部 | 项目标题 |
| project_description | string | 是 | 全部 | 项目描述 |
| company_name | string | 是 | 全部 | 公司名称（脱敏） |
| work_format | enum | 是 | 全部 | 远程/现场/混合 |
| project_cycle | enum | 是 | 全部 | 项目周期 |
| start_date | date | 否 | 全部 | 预计开始日期 |
| required_skills | array | 是 | 全部 | 技能要求列表 |
| hiring_count | number | 是 | 全部 | 招聘人数 |
| view_count | number | 否 | 全部 | 浏览次数 |
| application_count | number | 否 | 全部 | 申请人数 |
| status | enum | 是 | 全部 | 项目状态 |
| created_at | datetime | 是 | 全部 | 发布时间 |
| budget_range | object | 否 | 仅HR | 预算范围（私有） |
| internal_notes | string | 否 | 仅HR | 内部备注（私有） |

**项目详情扩展字段：**

| 字段名 | 类型 | 必填 | 可见性 | 说明 |
|--------|------|------|--------|------|
| project_major_categories | array | 是 | 全部 | 主技能分类 |
| project_sub_categories | array | 是 | 全部 | 子技能分类 |
| language_requirements | array | 否 | 全部 | 语言要求 |
| work_requirements | string | 否 | 全部 | 工作要求详情 |
| project_location | object | 否 | 全部 | 工作地点 |
| expiry_date | date | 否 | 全部 | 截止日期 |

#### 操作流程

**流程1：顾问投递申请**

```
步骤1: 顾问浏览项目列表
       └─→ 操作：筛选、搜索、排序
       └─→ 输入：关键词、技能筛选、地点筛选
       └─→ 输出：项目列表

步骤2: 查看项目详情
       └─→ 操作：点击项目卡片
       └─→ 输出：项目完整信息

步骤3: 点击"投递申请"
       └─→ 前置条件：已登录、角色为顾问
       └─→ 操作：填写申请表单
       └─→ 字段：
            - 期望薪资（必填）
            - 可开始时间（必填）
            - 自我介绍（选填）
            - 附件简历（选填）

步骤4: 提交申请
       └─→ 验证：
            - 同一项目不能重复申请
            - 项目状态必须为"发布"
       └─→ 系统动作：
            - 创建申请记录
            - 发送通知给HR
            - 更新项目申请计数

步骤5: 申请结果
       └─→ 成功：显示成功提示，跳转到"我的申请"
       └─→ 失败：显示错误原因
```

#### 状态流转

**项目状态：**
```
草稿 → 发布 → 进行中 → 已关闭 → 已到期
         ↓
      已下架
```

**申请状态：**
```
待查看 → 待面试 → 已通过 → 已签约
    ↓         ↓
  已拒绝    已拒绝
```

#### 跨流程关联

| 关联功能 | 关联点 | 关联逻辑 |
|----------|--------|----------|
| 项目子项管理 | 申请通过后 | HR创建ProjectAssignment时关联申请记录 |
| 合同管理 | 签约阶段 | 申请记录关联合同 |
| 通知系统 | 状态变更 | 申请状态变更时发送通知 |
| 用户档案 | 技能匹配 | 基于顾问技能推荐项目 |

#### 测试要点

1. **功能测试**
   - 项目列表分页、筛选、排序
   - 项目详情显示完整
   - 申请表单验证
   - 重复申请拦截

2. **权限测试**
   - 未登录用户不能申请
   - HR角色不能申请项目
   - 私有字段不可见

3. **跨流程测试**
   - 申请后HR收到通知
   - 申请通过后可创建项目子项
   - 项目关闭后不能申请

## 2. 项目子项管理模块

### 2.1 创建项目子项（HR操作）

HR为顾问创建项目子项，设置结算单价和里程碑

#### 角色权限矩阵

| 操作 | 顾问 | HR | 企业管理员 | 管理员 |
|------|------|-----|------------|--------|
| 创建项目子项 | ❌ | ✅ | ✅ | ✅ |

| 查看自己子项 | ✅ | - | - | - |
| 修改结算单价 | ❌ | ✅ | ✅ | ✅ |

#### 操作流程

**流程1：HR创建项目子项**

```
步骤1: HR进入项目详情页
       └─→ 点击"添加顾问"按钮
       └─→ 前置条件：项目状态为"发布"或"进行中"

步骤2: 选择顾问
       └─→ 操作：搜索或从人才库选择
       └─→ 验证：
            - 顾问状态不能为"已下线"
            - 同一项目同一顾问不能重复
       └─→ 显示：顾问基本信息、状态、技能

步骤3: 设置结算信息
       └─→ 字段填写：
            - 结算类型（必填）：日薪/时薪/月薪/固定
            - 结算单价（必填）：数字
            - 货币类型（必填）：CNY/USD/EUR
            - 付款周期（必填）：周结/双周结/月结/里程碑
            - 计费方式（必填）：按工时/按天数/固定
       └─→ 验证：单价必须大于0

步骤4: 设置里程碑（可选）
       └─→ 操作：添加里程碑
       └─→ 字段填写：
            - 里程碑名称（必填）
            - 开始日期（必填）
            - 结束日期（必填）
            - 付款金额（可选）
            - 交付物（可选）
       └─→ 验证：
            - 日期不能重叠
            - 总金额不能超过预算

步骤5: 设置项目时间
       └─→ 字段填写：
            - 项目开始日期（必填）
            - 项目结束日期（可选）

步骤6: 提交创建
       └─→ 系统动作：
            - 创建ProjectAssignment记录
            - 状态设为"pending"
            - 发送通知给顾问
       └─→ 输出：创建成功提示
```

**流程2：顾问确认项目子项**

```
步骤1: 顾问收到通知
       └─→ 点击通知进入项目子项详情
       └─→ 显示：项目信息、结算信息、里程碑

步骤2: 顾问审核信息
       └─→ 检查：结算单价、付款周期、里程碑

步骤3: 确认或拒绝
       └─→ 确认：
            - 状态变更为"confirmed"
            - 等待项目开始
       └─→ 拒绝：
            - 状态变更为"rejected"
            - 需填写拒绝原因
            - 通知HR
```

#### 状态流转

```
┌─────────────────────────────────────────────────────────────────┐
│              ProjectAssignment 状态流转                          │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  [HR创建]                                                        │
│      │                                                          │
│      ▼                                                          │
│  pending ──────────────────────────────────────────────────────│
│      │                                                          │
│      ├──────→ confirmed ────→ active ────→ completed           │
│      │            │              │             │                │
│      │            │              │             │                │
│      ▼            ▼              ▼             ▼                │
│   rejected    [取消]        terminated     [归档]              │
│                                                                 │
│  状态说明:                                                       │
│  • pending: HR创建，等待顾问确认                                 │
│  • confirmed: 顾问已确认，等待项目开始                           │
│  • active: 项目进行中，可提交工单                                │
│  • completed: 项目已完成                                         │
│  • rejected: 顾问已拒绝                                          │
│  • terminated: 项目已终止                                        │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

#### 跨流程关联

| 关联功能 | 关联点 | 关联逻辑 |
|----------|--------|----------|
| 工单管理 | 工单创建 | 工单必须关联active状态的Assignment |
| 付款管理 | 付款计算 | 付款金额基于Assignment的结算单价 |
| 项目管理 | 项目状态 | Assignment状态影响项目状态 |
| 合同管理 | 合同签署 | 合同关联到Assignment |
| 顾问状态 | 状态更新 | Assignment开始后顾问状态变为"项目中" |
| 技能匹配 | 推荐权重 | Assignment完成后的评价影响推荐 |

#### 数据约束

1. **唯一性约束**
   - 同一项目同一顾问只能有一个Assignment

2. **状态约束**
   - 只有active状态才能创建工单
   - 只有completed状态才能归档

3. **金额约束**
   - 里程碑总金额 ≤ 项目预算
   - 已付金额 ≤ 总金额

4. **时间约束**
   - 开始日期 ≤ 结束日期
   - 里程碑时间在项目时间内

#### 测试要点

1. **功能测试**
   - 创建项目子项完整流程
   - 结算信息设置
   - 里程碑管理
   - 状态流转

2. **权限测试**
   - 只有HR能创建
   - 只有顾问能确认
   - 结算单价仅HR和对应顾问可见

3. **数据约束测试**
   - 重复创建拦截
   - 金额约束验证
   - 时间约束验证

4. **跨流程测试**
   - 确认后顾问状态更新
   - active后可创建工单
   - completed后触发简历更新

## 3. 工单管理模块

### 3.1 提交工单（顾问操作）

#### 功能概述

#### 角色权限矩阵

| 操作 | 顾问 | HR | 企业管理员 | 管理员 |

#### 操作流程

**流程1：顾问创建并提交工单**

```
步骤1: 顾问进入"我的项目"
       └─→ 选择进行中的项目
       └─→ 点击"提交工单"
       └─→ 前置条件：Assignment状态为active

步骤2: 选择里程碑
       └─→ 操作：从下拉列表选择里程碑
       └─→ 显示：里程碑名称、时间范围
       └─→ 验证：里程碑状态不能为已完成

步骤3: 填写工作信息
       └─→ 字段填写：
            - 工作开始日期（必填）
            - 工作结束日期（必填）
            - 工作小时数（必填）
            - 工作天数（选填）
            - 工作内容描述（必填）
            - 交付物附件（选填）
       └─→ 验证：
            - 日期在里程碑时间范围内
            - 工时大于0

步骤4: 系统自动计算金额
       └─→ 计算逻辑：
            - 按天数：金额 = 天数 × 日薪单价
            - 按工时：金额 = 工时 × 时薪单价
            - 固定：金额 = 里程碑固定金额
       └─→ 显示：结算单价（只读）、计算金额
       └─→ 说明：结算单价从Assignment读取，不可修改

步骤5: 预览并提交
       └─→ 显示：工单完整信息预览
       └─→ 操作：点击"提交审批"
       └─→ 系统动作：
            - 状态变更为"submitted"
            - 记录提交时间
            - 发送通知给HR

步骤6: 提交结果
       └─→ 成功：显示成功提示，跳转到工单列表
       └─→ 失败：显示错误原因
```

**流程2：HR审批工单**

```
步骤1: HR收到通知
       └─→ 点击通知进入工单详情
       └─→ 显示：工单完整信息

步骤2: HR审核工作成果
       └─→ 检查：
            - 工作内容是否完整
            - 工时是否合理
            - 交付物是否符合要求

步骤3: 审批操作
       └─→ 通过：
            - 填写审批意见（选填）
            - 状态变更为"approved"
            - 发送通知给顾问
            - 顾问可申请付款
       └─→ 驳回：
            - 填写驳回原因（必填）
            - 状态变更为"rejected"
            - 发送通知给顾问
            - 顾问可修改后重新提交
```

**流程3：顾问申请付款**

```
步骤1: 顾问查看已审批工单
       └─→ 工单状态为"approved"
       └─→ 点击"申请付款"

步骤2: 确认付款信息
       └─→ 显示：付款金额、收款账户
       └─→ 操作：确认申请

步骤3: 系统处理
       └─→ 状态变更为"payment_pending"
       └─→ 发送通知给HR
```

**流程4：HR付款并上传凭证**

```
步骤1: HR查看待付款工单
       └─→ 工单状态为"payment_pending"
       └─→ 点击"确认付款"

步骤2: 填写付款信息
       └─→ 字段填写：
            - 付款方式（必填）
            - 交易流水号（选填）
            - 付款凭证（必填，上传）

步骤3: 确认付款
       └─→ 系统动作：
            - 状态变更为"paid"
            - 记录付款时间
            - 更新Assignment已付金额
            - 发送通知给顾问
```

**流程5：顾问确认收款**

```
步骤1: 顾问查看已付款工单
       └─→ 工单状态为"paid"
       └─→ 查看付款凭证

步骤2: 确认收款
       └─→ 操作：点击"确认收款"
       └─→ 系统动作：
            - 状态变更为"completed"
            - 更新里程碑状态
            - 检查是否所有里程碑完成
            - 如全部完成，更新Assignment状态为completed
```

**流程6：异议处理**

```
步骤1: 顾问/HR提交异议
       └─→ 前置条件：工单状态为submitted/approved/payment_pending
       └─→ 填写异议原因（必填）
       └─→ 状态变更为"disputed"

步骤2: 管理员处理异议
       └─→ 查看异议详情
       └─→ 联系双方了解情况
       └─→ 填写解决方案
       └─→ 状态变更为"resolved"

步骤3: 异议解决后
       └─→ 工单恢复到之前的状态继续流程
```

       └─→ 查看申请列表

       └─→ 通过申请

       └─→ 设置结算单价
       └─→ 设置里程碑
       └─→ 发送给顾问确认

步骤4: 顾问确认项目子项
       └─→ 查看结算信息
       └─→ 确认接受

步骤5: 项目开始
       └─→ Assignment状态变为active
       └─→ 顾问状态变为"项目中"

步骤6: 顾问提交工单
       └─→ 选择里程碑
       └─→ 填写工作内容
       └─→ 提交审批

步骤7: HR审批工单
       └─→ 审核工作成果
       └─→ 通过审批

步骤8: 顾问申请付款
       └─→ 确认付款信息
       └─→ 提交申请

步骤9: HR付款
       └─→ 上传付款凭证
       └─→ 确认付款

步骤10: 顾问确认收款
       └─→ 查看凭证

       └─→ Assignment状态变为completed

### 6.2 数据一致性验证点

| 验证点 | 验证内容 | 验证时机 |
|--------|----------|----------|
| 结算单价一致性 | 工单单价 = Assignment单价 | 工单创建时 |
| 金额一致性 | 工单金额 = 工时 × 单价 | 工单创建时 |
| 统计一致性 | Assignment总金额 = SUM(工单金额) | 工单完成时 |
| 状态一致性 | 顾问状态 = Assignment状态映射 | 状态变更时 |
| 里程碑一致性 | 里程碑完成 = 所有工单完成 | 工单完成时 |
