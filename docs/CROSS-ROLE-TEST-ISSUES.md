## 测试覆盖场景

本次测试覆盖了以下业务流程：

### 流程A: 正常项目执行流程
1. HR创建项目 → 顾问浏览项目 → 顾问申请项目 → HR审批通过 → 顾问填报工时 → HR确认工时 → 顾问创建发票 → HR审核发票 → HR确认付款 → 顾问确认收款 → 双方评价

### 流程B: 工时驳回重提流程
1. 顾问填报工时 → HR驳回工时 → 顾问查看驳回原因 → 顾问修改重提 → HR确认工时

### 流程C: 发票驳回重提流程
1. 顾问创建发票 → HR驳回发票 → 顾问修改重提 → HR审核通过

### 流程D: 举报处理流程
1. 用户提交举报 → 管理员查看举报 → 管理员开始调查 → 管理员验证举报

## 业务逻辑一致性验证结果

### 工时状态流转规则 ✅
```
draft -> submitted
submitted -> confirmed/rejected
rejected -> submitted
confirmed -> invoiced
invoiced -> paid
```

### 发票状态流转规则 ✅
```
draft -> submitted
submitted -> approved/rejected
rejected -> submitted
approved -> paid
```

### 项目申请状态一致性 ⚠️
- 已申请的项目应显示"已申请"状态或隐藏申请按钮
- 需要在前端实现状态显示逻辑
