## 3. 状态变更条件与互斥逻辑

### 3.1 项目状态变更条件

| 变更操作 | 前置条件 | 后置条件 | 互斥条件 |
|----------|----------|----------|----------|
| 发布项目 | status = draft | status = published | 无 |
| 接受申请 | status = published, 存在pending申请 | status = in_progress | 其他pending申请变为invalidated |
| 关闭项目 | status in [published, in_progress] | status = closed | 存在未完成的工时需提示 |
| 重新开放 | status = closed | status = published | 无 |
| 项目到期 | status = published, 超过deadline | status = expired | 无 |

### 3.2 申请状态变更条件

| 变更操作 | 前置条件 | 后置条件 | 互斥条件 |
|----------|----------|----------|----------|
| 提交申请 | 项目status = published, 用户未申请过 | status = pending | 项目已有accepted申请时禁止申请 |
| 查看申请 | status = pending | status = reviewed | 无 |
| 接受申请 | status in [pending, reviewed] | status = accepted, 项目status = in_progress | 同项目其他accepted申请存在时禁止 |
| 拒绝申请 | status in [pending, reviewed] | status = rejected | 无 |
| 撤回申请 | status = pending | status = withdrawn | 无 |

### 3.3 工时状态变更条件

| 变更操作 | 前置条件 | 后置条件 | 互斥条件 |
|----------|----------|----------|----------|
| 创建工时 | 项目status = in_progress, 顾问在项目中 | status = draft | 同一天同一项目只能有一条记录 |
| 编辑工时 | status = draft | status = draft | 无 |
| 提交工时 | status in [draft, rejected] | status = submitted | 无 |
| 确认工时 | status = submitted | status = confirmed | 无 |
| 驳回工时 | status = submitted | status = rejected | 必须填写驳回原因 |
| 工时开票 | status = confirmed | status = invoiced | 同一工时只能开一次票 |
| 工时付款 | status = invoiced, 发票status = paid | status = paid | 无 |

### 3.4 发票状态变更条件

| 变更操作 | 前置条件 | 后置条件 | 互斥条件 |
|----------|----------|----------|----------|
| 创建发票 | 存在confirmed工时 | status = draft | 同一工时只能关联一次 |
| 编辑发票 | status = draft | status = draft | 无 |
| 提交发票 | status in [draft, rejected] | status = submitted | 无 |
| 批准发票 | status = submitted | status = approved | 无 |
| 驳回发票 | status = submitted | status = rejected | 必须填写驳回原因 |
| 确认付款 | status = approved | status = paid | 无 |
| 确认收款 | status = paid | status = received | 无 |

## 4. 异常流程处理

### 4.1 已付款项目的限制

| 场景 | 限制规则 |
|------|----------|
| 顾问撤回已开票工时 | 禁止：工时状态为invoiced或paid时不可撤回 |
| HR删除已付款项目 | 禁止：项目有关联的paid发票时不可删除 |
| 顾问修改已确认工时 | 禁止：工时状态为confirmed及以上不可修改 |
| HR驳回已开票工时 | 禁止：工时已关联发票时不可驳回 |

### 4.2 项目关闭后的限制

| 角色 | 限制规则 |
|------|----------|
| HR | 不能编辑项目信息，不能接受新申请 |
| 顾问 | 不能提交新工时，不能创建新发票 |
| 系统 | 项目变为只读，仅可查看历史记录 |

### 4.3 数据一致性约束

| 约束规则 | 描述 |
|----------|------|
| 工时-项目关联 | 工时只能关联status = in_progress的项目 |
| 发票-工时关联 | 发票只能关联status = confirmed的工时 |
| 申请-项目关联 | 申请只能针对status = published的项目 |
| 付款-发票关联 | 付款只能针对status = approved的发票 |
