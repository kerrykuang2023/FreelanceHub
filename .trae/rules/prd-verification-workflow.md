# PRD功能实现检查工作规范

## 1. 概述

本规范定义了确保开发任务与PRD规划完全一致的标准检查流程。所有开发任务必须遵循此规范执行。

## 2. 工作流程

### 2.1 任务开始前

1. **阅读PRD文档**
   - 定位PRD文档路径: `docs/PRD-Freelancer-Platform.md`
   - 识别当前任务相关的功能模块
   - 记录所有相关功能ID和详细需求

2. **创建任务检查清单**
   - 从PRD提取功能列表
   - 标注每个功能的优先级(P0/P1/P2)
   - 记录预期路径和UI元素

### 2.2 开发过程中

1. **逐项实现功能**
   - 按P0 > P1 > P2优先级顺序开发
   - 每完成一个功能，更新检查清单状态
   - 确保UI元素与PRD描述一致

2. **代码质量检查**
   - 运行TypeScript类型检查
   - 运行ESLint检查
   - 确保无编译错误

### 2.3 任务完成后

1. **运行E2E测试**
   - 测试必须包含认证流程
   - 测试所有已实现功能
   - 生成测试报告

2. **PRD对照检查**
   - 使用检查清单逐项验证
   - 记录缺失功能
   - 记录部分实现功能

3. **生成下一阶段计划**
   - 将缺失功能加入待办
   - 按优先级排序
   - 估算工作量

## 3. 检查清单格式

```markdown
## [模块名称] 模块检查清单

| 功能ID | 功能名称 | 优先级 | PRD要求 | 实现状态 | 验证结果 | 备注 |
|--------|----------|--------|---------|----------|----------|------|
| XXX-001 | 功能名 | P0 | 详细描述 | ✅/⚠️/❌ | 通过/失败 | 说明 |
```

### 状态定义

- ✅ 已完成: 功能完全实现，测试通过
- ⚠️ 部分完成: 核心功能实现，细节待完善
- ❌ 未完成: 功能未实现或测试失败

## 4. 验证标准

### 4.1 UI验证

- [ ] 页面路径与PRD定义一致
- [ ] 表单字段与PRD定义一致
- [ ] 按钮操作与PRD定义一致
- [ ] 状态显示与PRD定义一致

### 4.2 功能验证

- [ ] 正常流程可执行
- [ ] 异常处理正确
- [ ] 边界条件处理
- [ ] 权限控制正确

### 4.3 API验证

- [ ] 接口路径与PRD定义一致
- [ ] 请求参数完整
- [ ] 响应格式正确
- [ ] 错误处理完善

## 6. 持续改进

1. 每次迭代后更新检查清单
2. 记录发现的问题和解决方案
3. 优化验证流程
4. 更新测试用例
