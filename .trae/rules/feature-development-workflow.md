# 功能开发与验证闭环工作规范

## 1. 概述

本规范定义了从任务接收到最终交付的完整流程，确保每个功能都能完整、准确地实现并通过验证。

## 2. 核心原则

### 2.1 验证驱动开发 (VDD)
- **先定义验证标准，再开始开发**
- **没有通过验证的功能不算完成**
- **每个功能必须有可追溯的测试证据**

### 2.2 增量验证原则
- **完成一个功能，验证一个功能**
- **禁止批量开发后一次性验证**
- **每次修改后必须重新验证相关功能**

### 2.3 PRD对照原则
- **所有功能必须可追溯到PRD需求**
- **实现必须与PRD描述完全一致**
- **任何偏差都必须记录并确认**

## 3. 工作流程

### 3.1 任务接收阶段

```
步骤1: 解析任务指令
├── 提取任务目标
├── 识别涉及的角色（自由顾问/企业用户/管理员）
├── 识别涉及的功能模块
└── 确定优先级

步骤2: 阅读PRD文档 【强制执行】
├── 定位相关功能章节
├── 提取功能ID和详细描述
├── 记录UI元素要求
├── 记录交互行为要求
├── 记录数据字段要求
└── 【关键】生成功能点清单表格

步骤3: 创建功能清单 【强制执行】
├── 列出所有待实现功能
├── 标注每个功能的PRD来源（功能ID）
├── 定义验收标准
├── 创建检查清单文件
└── 【关键】将清单写入TodoWrite工具
```

### 3.2 功能开发阶段

```
步骤1: 分析现有代码
├── 检查相关页面是否存在
├── 检查相关组件是否存在
├── 检查相关API是否存在
└── 记录需要新建/修改的文件

步骤2: 实现功能
├── 添加data-testid属性（用于测试定位）
├── 实现UI组件
├── 实现交互逻辑
├── 对接后端API
└── 处理错误情况

步骤3: 自检
├── 检查TypeScript编译
├── 检查ESLint
├── 检查控制台错误
└── 手动验证基本功能
```

### 3.3 验证阶段 【核心环节】

```
步骤1: 编写E2E测试用例
├── 使用精确的data-testid选择器
├── 验证页面可访问性
├── 验证UI元素存在性
├── 验证交互行为正确性
└── 生成截图证据

步骤2: 运行测试 【强制执行】
├── 执行E2E测试
├── 收集测试结果
├── 保存截图
├── 生成测试报告
└── 【关键】测试必须全部通过才能继续

步骤3: PRD逐项对照 【强制执行】
├── 【关键】逐项对照PRD要求
├── 【关键】检查每个功能ID是否实现
├── 记录差异
├── 记录缺失功能
├── 更新检查清单
└── 【关键】如有缺失项，立即修复，不可跳过

步骤4: 修复问题
├── 分析问题根因
├── 实施修复
├── 重新运行测试
└── 确认问题解决

步骤5: 循环验证 【强制执行】
├── 检查是否所有功能ID都已实现
├── 如有未完成项，返回步骤1
├── 直到所有功能ID 100%完成
└── 更新检查清单状态
```

### 3.4 完成确认阶段 【最终验收】

```
步骤1: 完成度检查 【强制执行】
├── 【关键】检查所有PRD功能ID是否已实现
├── 【关键】检查所有E2E测试是否通过
├── 所有截图已保存
├── 检查清单已更新
├── 无遗留问题
└── 【关键】如有未完成项，返回3.3继续

步骤2: 重新构建 【强制执行】
├── 清理构建缓存
├── 重新构建项目
├── 启动服务
└── 运行完整E2E测试

步骤3: 最终验证 【强制执行】
├── 运行完整测试套件
├── 检查所有截图
├── 确认所有功能正常
├── 更新PRD检查清单
├── 【关键】生成完成度报告
└── 【关键】确认100%完成才可结束任务

步骤4: 生成下一阶段计划
├── 如有P1/P2功能未完成，加入待办
├── 按优先级排序
├── 记录到检查清单
└── 汇报完成情况
```

任务完成前必须通过以下检查点：

| 检查点 | 检查内容 | 通过条件 | 不通过处理 |

| CP1 | PRD功能ID提取 | 所有相关功能ID已列出 | 返回重新分析PRD |

| CP5 | 截图证据 | 所有功能有截图 | 补充截图 |
| CP6 | 检查清单 | 清单已更新 | 更新清单 |

## 5. 功能完成标准

### 5.1 必须满足的条件

每个功能点必须满足以下所有条件才能标记为"已完成"：

| 条件 | 验证方式 | 证据要求 |
|------|----------|----------|
| 页面可访问 | E2E测试访问成功 | 截图 |
| UI元素完整 | 所有PRD要求的元素存在 | 截图+测试日志 |
| 交互正确 | 按钮点击、表单提交正常 | 测试日志 |
| 数据正确 | 数据展示和提交符合PRD | 测试日志 |
| 无控制台错误 | 浏览器控制台无错误 | 截图 |
| TypeScript通过 | tsc编译无错误 | 命令输出 |
| ESLint通过 | lint检查无错误 | 命令输出 |

### 5.2 状态定义

```markdown
- ✅ 已完成: 所有条件满足，E2E测试通过
- ⚠️ 部分完成: 核心功能存在，但有缺失项
- ❌ 未完成: 功能不存在或测试失败
- 🔄 修复中: 已发现问题，正在修复
- 🚫 阻塞: 依赖其他功能或外部因素
```

## 6. 测试规范

### 6.1 选择器规范

```typescript
// ✅ 推荐：使用data-testid
await page.locator('[data-testid="submit-btn"]')

// ✅ 可接受：语义化选择器
await page.locator('button[type="submit"]')
await page.locator('input[name="email"]')

// ❌ 禁止：模糊选择器
await page.locator('[class*="button"]')  // 不可靠
await page.locator('div > div > button')  // 脆弱
```

### 6.2 测试用例模板

```typescript
test('FEATURE-ID: 功能名称', async ({ page }) => {
  // 1. 访问页面
  await page.goto(`${BASE_URL}/path`);
  await page.waitForLoadState('networkidle');
  
  // 2. 截图
  await page.screenshot({ path: `screenshots/feature-id.png` });
  
  // 3. 验证元素存在
  await expect(page.locator('[data-testid="element"]')).toBeVisible();
  
  // 4. 验证交互行为
  await page.click('[data-testid="submit-btn"]');
  
  // 5. 验证结果
  await expect(page).toHaveURL(/success/);
});
```

## 7. 问题处理流程

### 7.1 问题分类

| 级别 | 定义 | 处理时限 |
|------|------|----------|
| P0-阻塞 | 核心功能无法使用 | 立即处理 |
| P1-严重 | 主要功能受损 | 当日内处理 |
| P2-一般 | 次要功能问题 | 2日内处理 |
| P3-轻微 | UI/体验问题 | 迭代中处理 |

## 9. 禁止事项

### 9.1 绝对禁止

- ❌ **禁止**在E2E测试通过前标记功能完成
- ❌ **禁止**批量开发后一次性验证
- ❌ **禁止**跳过PRD对照环节
- ❌ **禁止**忽略测试失败结果
- ❌ **禁止**修改测试用例来通过测试（应修复功能）
- ❌ **禁止**在任务完成前不生成完成报告
- ❌ **禁止**跳过功能ID检查直接结束任务
- ❌ **禁止**忽略PRD中的任何功能点

### 9.2 强制执行

- ✅ **必须**每个功能都有对应的测试用例
- ✅ **必须**保存截图作为验证证据
- ✅ **必须**更新功能检查清单
- ✅ **必须**在修改后重新验证
- ✅ **必须**记录所有发现的问题
- ✅ **必须**生成功能ID对照检查表
- ✅ **必须**在任务结束时汇报完成情况
- ✅ **必须**将未完成功能加入下一阶段计划

### 9.3 任务结束条件

任务只有在满足以下所有条件时才能结束：

1. **功能完整性**: 所有PRD定义的功能ID都已实现
2. **测试通过**: 所有E2E测试用例通过
3. **截图完整**: 所有功能有截图证据
4. **清单更新**: PRD-Feature-Checklist.md已更新
5. **报告生成**: 已生成任务完成报告
6. **遗留记录**: 未完成功能已记录到下一阶段计划

## 11. 验证闭环机制 【核心规范】

### 11.1 闭环机制概述

验证闭环机制确保每个任务从开始到结束都有完整的验证链条，防止功能遗漏和实现偏差。

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                           验证闭环机制流程图                                    │
└─────────────────────────────────────────────────────────────────────────────┘

    ┌─────────────┐
    │  任务开始    │
    └──────┬──────┘
           │
           ▼
    ┌─────────────────────────────────────────────────────────────┐
    │  阶段1: PRD解析                                              │
    │  ├── 读取PRD文档                                             │
    │  ├── 提取所有相关功能ID                                       │
    │  ├── 生成功能ID清单                                          │
    │  └── 写入TodoWrite工具                                       │
    └──────────────────────────┬──────────────────────────────────┘
                               │
                               ▼
    ┌─────────────────────────────────────────────────────────────┐
    │  阶段2: 功能实现                                              │
    │  ├── 按功能ID逐个实现                                         │
    │  ├── 每完成一个标记Todo状态                                    │
    │  └── 实现完成后自检                                           │
    └──────────────────────────┬──────────────────────────────────┘
```

## 14. 主数据依赖检查 【强制执行】

> **说明:** 在执行E2E测试前，必须检查主数据是否已准备完毕。

### 14.1 主数据检查清单

在执行任何业务流程测试前，必须验证以下主数据：

| 主数据类型 | 检查项 | 验证方式 |
|-----------|--------|----------|
| 公司信息 | 至少存在1家终端企业 | API查询或管理后台查看 |
| 公司信息 | 至少存在1家挂靠企业 | API查询或管理后台查看 |
| 技能分类 | 至少存在2个技能大类 | API查询或管理后台查看 |
| 技能分类 | 每个大类下至少2个小类 | API查询或管理后台查看 |
| 测试用户 | 顾问、HR、管理员各至少1个 | 登录验证 |
| 枚举配置 | 所有枚举类型都有值 | API查询或前端下拉框 |

### 14.2 主数据缺失处理

```
检查主数据
    │
    ├─ 存在 ──▶ 继续测试
    │
    └─ 缺失 ──▶ 创建主数据
                    │
                    ├─ 管理后台可访问 ──▶ 通过管理后台创建
                    │
                    └─ 管理后台不可访问 ──▶ 通过API或数据库直接创建
                                              │
                                              └─ 记录到PRD反馈
```
