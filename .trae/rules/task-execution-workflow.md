## 3. 任务复杂度判断标准

### 3.1 简单任务（使用 superdev）

| 判断条件 | 示例 |
|---------|------|
| 单一功能修改 | 修复一个按钮样式 |
| 小范围代码调整 | 修改一个API调用 |
| 已有明确方案 | 按照现有模式添加字段 |
| 预计耗时 < 30分钟 | 更新配置文件 |

### 3.2 复杂任务（使用 superpower-loop）

| 判断条件 | 示例 |
|---------|------|
| 多功能开发 | 实现完整的用户认证系统 |
| 跨模块修改 | 重构数据流涉及多个组件 |
| 需要架构设计 | 添加新的业务模块 |
| 涉及数据库变更 | 新增表结构和关联关系 |
| 预计耗时 > 30分钟 | 开发完整的CRUD功能 |

## 4. 技能调用规范

### 4.1 superdev 技能

**调用时机：** 简单任务或需要快速分析的问题

**执行流程：**
```
1. 调用 Skill tool，name="superdev"
2. 分析问题/需求
3. 制定解决方案
4. 实现代码修改
5. 验证修改效果
```

### 4.2 superpower-loop 技能

**调用时机：** 复杂任务需要迭代开发

**执行流程：**
```
1. 调用 Skill tool，name="superpower-loop"
2. 任务分解与优先级排序
3. 启动 Red/Green Agent 循环
4. 迭代开发每个子任务
5. 持续验证和优化
```

### 4.3 playwright 技能

**调用时机：** 所有开发完成后进行端到端测试

**测试清单：**

```markdown
## E2E测试检查清单

### 功能测试
- [ ] 页面正常加载，无白屏
- [ ] 所有表单字段可正常输入
- [ ] 表单验证正常工作
- [ ] 提交操作成功执行
- [ ] 成功/错误提示正确显示
- [ ] 数据正确保存和展示

### 跨角色场景验证
- [ ] 管理员角色操作正常
- [ ] HR角色操作正常
- [ ] 自由顾问角色操作正常
- [ ] 角色权限正确限制
- [ ] 数据隔离正确

### 数据一致性验证
- [ ] API返回数据正确
- [ ] 数据库存储数据正确
- [ ] 前端展示数据正确
- [ ] 三者数据一致

### 用户体验测试
- [ ] 操作流程直观顺畅
- [ ] 错误提示清晰友好
- [ ] 页面跳转正确
- [ ] 加载状态合理
- [ ] 响应时间可接受
```

## 5. 问题记录模板

当测试发现问题时，使用以下格式记录：

```markdown
## 问题记录

### 问题ID: ISS-XXX
| 字段 | 内容 |
|------|------|
| 发现时间 | YYYY-MM-DD HH:mm |
| 问题类型 | 功能缺陷 / 逻辑错误 / UI问题 / 性能问题 |
| 严重程度 | P0-阻塞 / P1-严重 / P2-一般 / P3-轻微 |
| 影响范围 | 受影响的功能模块 |
| 复现步骤 | 1. ... 2. ... 3. ... |
| 预期结果 | 应该发生什么 |
| 实际结果 | 实际发生了什么 |
| 相关日志 | 控制台错误、网络请求等 |
| 截图证据 | 截图文件路径 |

### 分析与修复
| 字段 | 内容 |
|------|------|
| 根本原因 | 问题的根本原因 |
| 修复方案 | 如何修复 |
| 修改文件 | 涉及的文件列表 |
| 验证结果 | 修复后的测试结果 |
```

## 6. 任务完成标准

任务只有在满足以下所有条件时才算完成：

| 条件 | 验证方式 |
|------|----------|
| ✅ 所有代码修改完成 | 代码审查通过 |
| ✅ 功能测试全部通过 | playwright测试报告 |
| ✅ 跨角色场景验证通过 | 多角色E2E测试 |
| ✅ 数据一致性验证通过 | API + 数据库 + 前端对比 |
| ✅ 用户体验测试通过 | 操作流程验证 |
| ✅ 无遗留问题 | 问题清单为空 |
| ✅ 文档已更新 | README/API文档等 |

## 7. 工作流程示例

### 示例：开发一个新的报表功能

```
用户指令: "请开发一个项目工时统计报表功能"

Step 1: 任务分析
├── 判断复杂度: 复杂任务（涉及新功能、数据库、多页面）
├── 调用技能: superpower-loop
└── 输出: 任务分解列表

Step 2: 任务分解
├── 任务1: 设计数据库模型
├── 任务2: 开发后端API
├── 任务3: 开发前端页面
├── 任务4: 实现数据可视化
└── 任务5: 添加导出功能

Step 3: 迭代开发
├── 完成任务1 → 验证 → ✅
├── 完成任务2 → 验证 → ✅
├── 完成任务3 → 验证 → ✅
├── 完成任务4 → 验证 → ✅
└── 完成任务5 → 验证 → ✅

Step 4: E2E测试
├── 调用技能: playwright
├── 功能测试: ✅ 通过
├── 跨角色测试: 
│   ├── 管理员查看报表: ✅
│   ├── HR查看报表: ✅
│   └── 顾问查看报表: ✅
├── 数据一致性: ✅
└── 用户体验: ✅

Step 5: 问题修复循环
├── 发现问题: 导出功能在Safari浏览器异常
├── 记录问题: ISS-001
├── 调用技能: superdev 分析修复
├── 修复完成
├── 重新测试: ✅ 通过
└── 问题清单: 空

Step 6: 任务完成
└── 输出完成报告
```

## 8. 注意事项

1. **不要跳过任何阶段** - 每个阶段都有其重要性
2. **测试必须全面** - 不能只测试功能，还要验证数据一致性
3. **问题必须记录** - 即使是小问题也要记录，便于追踪
4. **循环直到完成** - 有问题就修复，修复后重新测试
5. **保持文档同步** - 代码变更后及时更新相关文档
